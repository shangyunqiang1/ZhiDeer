# 知时鹿首版范围与行为契约

日期：2026-10-24。状态：已确认；用户在 Q60 确认整体范围，本次产品需求访谈收口。

来源：用户提供的《知时鹿_产品需求文档_PRD_v0.1.md》及 [访谈决策](grilling-decisions.md)。本文是范围摘要，具体边界以逐项决策为依据；与原 PRD 冲突时，以访谈确认的调整为准。Q60 已确认保留文档所列未调整的原 PRD P0 功能及后续开发流程。此次工作为需求访谈和文档整理，尚未启动功能开发或技术验证。

## 目标和交付顺序

先满足用户本人每日使用，保留未来公开发布的可能。首条闭环是“一句话输入 → 准确解析 → 可编辑预览 → 确认保存 → 到点提醒 → 记录完成”；手动事项管理与本地提醒独立于网络和 AI。先验收核心闭环，再分别验收记忆、参谋，正式日常使用前具备手动备份恢复。（Q1–Q2、Q7、Q12、Q41）

先在 OPPO 主力手机验收，型号及 Android／系统版本待补充；随后扩大适配。原 PRD 的至少两家厂商测试要求作为后续扩大适配及发布门槛，不冒充个人首轮已完成。（Q8）

## 事项和时间

- 待办表示结果，可含截止时间；日程表示占用时间段。一个待办可关联多个日程，每个日程最多关联一个待办，各自确认完成；日程结束只表示时间已过。（Q3、Q11、Q19）
- 单个时间点且无持续时长，默认生成带截止时间的待办；明确时间段生成日程。预览可改类型；不擅猜时长，歧义先追问。（Q4、Q57）
- 只有日期的截止不补 23:59，当天显示今日到期，次日显示过期；提醒另设。安排固定创建时区，设备时区变化时提示并允许确认调整。（Q38–Q39）
- 首版只管理知时鹿本地日历，系统日历读取、导入和双向同步延后。（Q37）
- 父子任务分别确认完成；全部子任务完成不自动完成父待办，提前完成父待办时提示未完成步骤。提前完成或取消父待办时，经确认停止未完成子任务提醒，不改变子任务原状态。（Q40、Q53）
- 便签勾选清单独立于待办和子任务，首版不自动互转。（Q50）

## 重复待办

- 按固定日期产生各次待办，分别记录完成情况，本次未完成不阻止下一次出现。（Q17）
- 每月不存在的日期落在当月最后一天，并在预览说明；不因一次落到月末而改变后续原定日期规则。（Q18）
- 修改或取消支持仅本次、本次及以后，保留过去记录；单次延期不改变后续日期，同日两次须在预览提示。（Q22–Q23）
- 每次复制当期子任务步骤并重置完成状态，保留过去记录；步骤修改同样支持仅本次或本次及以后。（Q46）

## 提醒和系统闹钟

- 默认不自动设置提醒；明确要求或启用默认规则时才设置，保存前显示无提醒或逐项列出的时间。同一事项支持多个提醒，相同提醒去重。（Q5、Q9、Q48）
- 相对提醒跟随事项基准时间移动，独立时刻提醒不随之移动；预览展示结果及过期提醒。（Q51）
- 首版自有提醒为通知、提示音和振动。通知或精确提醒权限不足时，保留事项并标记提醒未就绪，提供修复入口，降级须确认。（Q6、Q13）
- 关机期间错过的提醒恢复后合并提示，不逐条补响、不自动延期或完成事项。（Q10）
- 起床等持续响铃需求通过系统时钟交接；保留待核对记录，不凭跳转成功宣称保存成功，也不同时自动创建自有提醒。切换自有提醒时提示检查系统闹钟。（Q6、Q16）
- 指定任意日历日期的持续响铃，首版不承诺；说明限制后可选知时鹿通知提醒或手动核对系统时钟，不丢弃日期。（Q56）

## 完成、取消、删除和恢复

- 完成待办后提示是否取消未来关联日程，未选择则保留并标记关联待办已完成；取消日程及提醒仍须确认。（Q24）
- 取消待办保留业务记录并停止其自身提醒，提示处理未来关联日程；删除与取消分开。（Q49）
- 删除日程仅删除日程及其提醒，保留待办及待办自身提醒；删除待办则保留日程、解除关联并取消待办自身提醒。（Q20、Q25）
- 普通日程、待办、便签进入回收站保留 30 天，可立即彻底删除；期间不提醒、不参与 AI 检索或建议。恢复仅处理未来提醒，错过的只提示，仍检查权限。（Q21、Q26）
- 父待办及子任务一起删除和恢复，删除时各自提醒停止；已经解除的日程关联在恢复时如何处理尚未确认，列入技术设计核对。（Q25、Q52）
- 将已完成或已取消待办恢复为未完成时，先展示清单，经确认重启未来提醒，过去提醒不补响。（Q54）

## AI、语音与操作回执

- 用户自行填写 DeepSeek Key，可测试连接；不引入账号、充值或应用代付。未配置或失败时手动功能可用。（Q12）
- 所有 AI 写入先预览再点击确认，查询在授权范围内直接执行。批量创建任一项校验失败则整批不保存，修正后重新确认。（Q14–Q15）
- 结果以真实执行记录为准；超时、退出或重复点击不重复创建，结果未知时显示待核实。（Q58）
- 当前消息之外的会话和少量相关记录，在说明并取得一次授权后按需发送，各类上下文可分别关闭；关闭后不擅自发送，提供本地列表或重新授权入口。（Q28、Q35）
- 按住说话、松手转写，文字可编辑，点击发送后提交 AI。播报默认关闭；知时鹿不持久保存原始录音。（Q31、Q36）
- 系统语音引擎的可用性及服务边界仍须实机核验，不把系统引擎等同于完全离线。（原 PRD 第 5.5 节）

## 长期记忆与参谋

- 首版仅显式“记住”并确认后保存，自动候选延后。新旧冲突先展示，由用户决定替换或补充适用条件，未确认不覆盖。（Q27、Q32）
- 删除来源时停用关联记忆，来源彻底删除时清理；恢复来源后不自动启用，需再次确认。（Q29、Q33）
- 删除记忆保留来源原文，但停止相关内容的长期偏好检索与个性化使用；删除来源原文须单独选择。（Q59）
- 首版参谋仅主动点击或提问时生成，每日自动建议延后；依据变化后旧建议需重新核对，禁止直接执行旧操作，重新生成并确认。（Q30、Q34）

## 备份与恢复

- 首版手动备份默认独立口令加密，不导出 API Key，说明内容及忘记口令无法恢复的责任。（Q41–Q42）
- 只支持整库替换；先核对备份并展示摘要，提示备份现有数据，确认后替换；首版不合并。（Q43）
- 恢复后暂停全部恢复的提醒，展示清单，确认后重建；AI 上下文授权重新确认。（Q44）
- 彻底删除仅作用于当前应用数据，不自动修改外部旧备份；旧备份由用户管理，恢复前提示旧数据可能重新出现。（Q45）

## 导航及原 PRD 保留项

五个底栏：首页、日历、便签、待办、小鹿；记忆、提醒、设置、回收站设二级入口。首页以今日安排和快捷记录为主。（Q47）

原 PRD 中未被上述决定调整的 P0 需求继续保留，包括月视图与日程列表、便签标题正文及标签置顶搜索、待办优先级与分类、对话历史及流式回复、记忆管理字段和来源、建议依据及反馈、权限诊断与脱敏日志。P1/P2 仍延后；验收条目须按更新后的首版范围映射，不将 P1 的下一系统闹钟读取列为 P0 阻塞。

原 PRD 第 16.1 节的 Issue 关联、测试、提交及依赖核验要求经 Q60 确认为后续开发流程；当前访谈不会据此自动创建 Issue、提交代码或启动开发。

## 技术验证与未决事项

1. 补充 OPPO 型号和系统版本，确定最低 Android 版本、基准设备及性能指标；不能在未知设备上承诺提醒可靠性。
2. 固定 MyBrain 提交后验证构建和核心闭环，再决定改造或独立工程；未承诺选用 MyBrain。原始仓库核查限制见访谈 Q55 后的说明。
3. 实际复用前核对固定版本许可证、依赖及未来分发路径；当前无分发授权方案结论。
4. 选择模型接入方式、Key 安全存储、语音引擎和提醒调度实现；以设备能力测试为依据。
5. 在数据设计阶段核对日期截止与时区计算、恢复后的关联、记忆停用对上下文组装的影响、备份格式与失败恢复。不将这些实现细节作为已完成设计。

上述项目留在 M0／技术设计阶段逐项决策。产品范围整体确认不等于技术验证完成，也不构成启动开发的请求。
