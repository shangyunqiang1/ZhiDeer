# 知时鹿 Android 首版规格

## Problem Statement

用户需要在中文 Android 手机上把随口想到的事情快速变成可靠的安排。目前日程、待办、便签与提醒容易分散，截止时间和执行时段容易混淆；AI 对话可能只口头答应而未实际保存，解析错误还可能导致错过事项。用户也需要在断网、未配置 AI 或权限不可用时继续管理本地记录，并掌握哪些个人信息被记住和发送给外部模型。

第一版先服务用户本人每日使用，优先在其 OPPO 主力手机验证完整闭环，保留未来公开发布的可能。首发结果必须是可核对的真实记录与提醒状态，而非 AI 的自然语言承诺。

## Solution

提供以本地日历、待办、便签和提醒为基础的个人助手。用户可以直接手动操作，也可以通过文字或按住说话提出请求；AI 先澄清歧义，再生成可编辑的操作提案，确认后由业务层执行，依据真实执行结果返回回执。

待办表示要完成的结果，日程表示占用的时间，两者通过关联协作并独立处理完成状态。支持固定日期重复待办、多个提醒、回收站、手动加密备份，以及显式保存且来源可追溯的长期记忆。参谋建议仅在用户主动请求时生成，依据变化后必须重新核对。所有手动核心能力及本地提醒独立于 AI 服务和网络。

先验收“一句话输入、解析、预览、确认保存、提醒、完成记录”的核心闭环，再分别验收记忆和参谋；正式日常使用前提供备份恢复。工程起点先验证固定提交的 MyBrain，再决定改造或独立实现。

## User Stories

1. 作为日常使用者，我希望通过首页、日历、便签、待办、小鹿五个底栏访问核心功能，以便快速找到所需操作。
2. 作为日常使用者，我希望首页突出下一事项、今日安排、待办风险及快捷记录，以便迅速了解今天该做什么。
3. 作为日常使用者，我希望记忆、提醒、设置和回收站有明确的二级入口，以便管理数据和权限。
4. 作为中文用户，我希望核心页面、日期、通知和错误提示使用简体中文，以便准确理解应用状态。
5. 作为离线用户，我希望无需配置 AI 即可新增、查看和编辑日历、待办及便签，以便网络或模型故障时仍能管理事项。
6. 作为日历用户，我希望通过月视图和当日日程列表创建、查看、编辑和删除本地日程，以便直接安排时间。
7. 作为日历用户，我希望记录日程标题、开始结束、时区、地点、备注、分类和提醒，以便保留安排的完整信息。
8. 作为日历用户，我希望无效时间被拒绝、跨日日程正确显示，以便避免错误安排。
9. 作为日历用户，我希望查询今日、明日和接下来七天的真实记录，以便获得可信的安排信息。
10. 作为待办用户，我希望记录待办状态、截止、优先级、类别和子任务，以便管理要完成的结果。
11. 作为待办用户，我希望按今天、即将到期、过期、全部和已完成查看事项，以便定位当前重点。
12. 作为待办用户，我希望截止时间与执行日程分开，以便不把最晚完成时间误认为已经占用的时段。
13. 作为待办用户，我希望只有日期的截止保持为日期截止，当天显示今日到期、次日显示过期，以便应用不擅自补具体时刻。
14. 作为时间管理用户，我希望一个待办可以安排多个日程、每个日程最多关联一个待办，以便把大任务分配到多个时段。
15. 作为时间管理用户，我希望日程结束仅表示时间已过，完成仍需主动确认，以便不把时间经过当成任务完成。
16. 作为时间管理用户，我希望删除日程只取消它及其提醒、保留关联待办，以便取消安排时不丢失目标。
17. 作为时间管理用户，我希望删除待办时保留关联日程并解除关联，以便保留原本的时间安排。
18. 作为待办用户，我希望完成待办时可以选择取消未来关联日程、未选择时保留，以便提前完成后合理处理时间安排。
19. 作为待办用户，我希望完成、延期和取消记录时间戳，历史可查询且可删除，以便追溯执行情况。
20. 作为待办用户，我希望取消与删除分开，取消后停止待办自身提醒但保留记录，以便表达决定不再执行。
21. 作为父待办用户，我希望子任务全部完成后仍由我确认父待办完成，以便判断整体结果是否达成。
22. 作为父待办用户，我希望提前完成父待办时看到未完成子任务且不被自动勾选，以便保持记录真实。
23. 作为父待办用户，我希望提前完成或取消时可以确认停止未完成子任务提醒，以便不改变完成记录也能避免无用提醒。
24. 作为父待办用户，我希望删除及恢复父待办时连同子任务一起处理，以便保持任务结构完整。
25. 作为重复待办用户，我希望设置每日、每周、每月规则及例外日期，以便管理固定事务。
26. 作为重复待办用户，我希望每次独立记录完成情况、本次未完成不阻止下一次出现，以便保留真实履行记录。
27. 作为重复待办用户，我希望每月不存在的日期落在当月最后一天，且预览说明该规则，以便明确二月等月份的执行日期。
28. 作为重复待办用户，我希望修改或取消时选择仅本次或本次及以后，并保留过去记录，以便安全调整重复安排。
29. 作为重复待办用户，我希望单次延期不改变后续日期，同日两次时有明确提示，以便不会悄悄改变整组计划。
30. 作为重复待办用户，我希望每次子任务步骤重新开始、过去记录保留，步骤修改也支持本次或本次及以后，以便反复执行同一流程。
31. 作为便签用户，我希望快速保存标题、正文、标签和置顶状态，以便随手记录信息。
32. 作为便签用户，我希望创建可勾选清单、按全文关键词搜索并定位原便签，以便快速整理和找回内容。
33. 作为便签用户，我希望清单项独立于待办，不自动创建或完成待办，以便保持轻量记录方式。
34. 作为便签用户，我希望 AI 创建便签保留原话并提供编辑入口，以便不会增加未经我陈述的事实。
35. 作为提醒用户，我希望截止和提醒分别设置，默认不自动提醒，以便避免未经选择的通知。
36. 作为提醒用户，我希望明确要求提醒或启用默认规则时，保存前看到无提醒或完整提醒清单，以便核对实际安排。
37. 作为提醒用户，我希望同一事项可以设置多个提醒、相同提醒去重，以便分阶段提醒且不重复打扰。
38. 作为提醒用户，我希望修改事项时间时相对提醒跟随移动、独立时刻提醒保持不变，并预览过期提醒，以便准确掌握变化。
39. 作为提醒用户，我希望收到本地通知、提示音和振动，以便在到点时关注事项。
40. 作为提醒用户，我希望权限不可用时仍能保存事项，但明确显示提醒未就绪及修复入口，降级须确认，以便知道哪些事项尚未得到可靠提醒。
41. 作为提醒用户，我希望设备重启后恢复有效调度、错过的提醒合并提示且不逐条补响，以便恢复使用时不过度打扰。
42. 作为提醒用户，我希望关机或错过提醒不会自动延期或完成待办，以便业务记录不被设备状态改变。
43. 作为跨时区用户，我希望首版安排固定创建时区，设备时区变化时提示并允许确认调整，以便避免静默改变时间。
44. 作为起床用户，我希望通过系统时钟设置持续响铃并打开系统闹钟列表，以便使用手机已有闹钟能力。
45. 作为系统闹钟用户，我希望交接记录明确显示待核对，不因跳转成功而宣称已保存，以便核实真实状态。
46. 作为系统闹钟用户，我希望切换自有提醒前提示检查系统闹钟、不自动同时创建两份，以便避免重复响。
47. 作为指定日期闹钟用户，我希望应用不丢弃日期，明确说明限制并提供通知提醒或手动系统时钟设置，以便不会收到日期错误的响铃承诺。
48. 作为不受支持设备的用户，我希望系统时钟交接失败时有明确反馈和可见回退，以便仍有处理办法。
49. 作为误删用户，我希望普通日程、待办及便签进入回收站保留三十天，并可立即彻底删除，以便按需恢复或清理。
50. 作为误删用户，我希望回收站记录不触发提醒、不参与 AI 检索或建议，以便删除立即影响后续使用。
51. 作为恢复用户，我希望恢复事项只重启未来提醒、错过的只提示且仍检查权限，以便不会突然补响。
52. 作为恢复用户，我希望将已完成或取消的待办改回未完成时，先核对提醒清单再恢复未来提醒，以便掌握恢复的影响。
53. 作为 AI 用户，我希望填写自己的 DeepSeek Key、模型标识和 Base URL 并测试连接，以便使用个人模型服务。
54. 作为 AI 用户，我希望 Key 掩码显示、安全存储且不进入日志，以便降低密钥暴露风险。
55. 作为 AI 用户，我希望有多轮中文聊天、流式回复、可恢复和删除的会话记录，以便连续处理事情。
56. 作为文字输入用户，我希望一句话生成可编辑的事项提案，以便降低录入成本。
57. 作为自然语言用户，我希望只有时间点时默认生成带截止的待办、明确时段生成日程，且可修改类型，以便不被擅自推断时长。
58. 作为自然语言用户，我希望模糊时间和指代先被追问、随后预览明确日期、对象、时区及规则，以便减少误操作。
59. 作为 AI 用户，我希望授权范围内查询直接执行、所有写入都经预览确认，以便高效查询并控制数据修改。
60. 作为批量录入用户，我希望逐项修改或移除提案，任一项校验失败则整批不保存，以便不会不知情地只创建部分内容。
61. 作为 AI 用户，我希望取消提案不改变数据库、取消会话不产生未确认操作，以便退出时不会执行隐含写入。
62. 作为 AI 用户，我希望操作结果依据真实记录，重复确认不会重复创建，结果未知时显示待核实，以便不因超时或重复点击产生重复事项。
63. 作为隐私用户，我希望当前消息以外的会话及少量相关记录先说明并取得一次授权，且各类上下文可分别关闭，以便控制外发数据。
64. 作为隐私用户，我希望关闭相关上下文后应用不擅自发送，而提供本地列表或重新授权入口，以便隐私选择真正生效。
65. 作为语音用户，我希望按住说话、松手转写、编辑后点击发送，以便提交前纠正识别错误。
66. 作为语音用户，我希望录音、识别及转写状态清晰，退出页面不隐蔽录音，以便始终知道麦克风状态。
67. 作为语音用户，我希望拒绝麦克风或缺少识别器时有中文说明和键盘回退，以便继续记录。
68. 作为语音用户，我希望中文答案播报默认关闭、可开关及随时停止，以便自主控制声音输出。
69. 作为语音隐私用户，我希望知时鹿不持久保存原始录音，以便减少不必要的语音数据留存。
70. 作为语音用户，我希望语音请求经过与文字相同的操作确认，以便输入方式不会绕过确认流程。
71. 作为记忆用户，我希望只有明确要求记住并确认后才保存长期记忆，以便聊天不会自动变成永久偏好。
72. 作为记忆用户，我希望查看、编辑、删除和暂停记忆，并查看类型、来源、确认状态、创建及验证时间和有效期，以便理解并纠正所记内容。
73. 作为记忆用户，我希望相关已授权记忆跨会话按需命中、过期或无来源内容不当作确定事实，以便获得有依据的个性化。
74. 作为记忆用户，我希望冲突记忆由我选择替换或补充条件，未确认不覆盖，以便不被错误更新偏好。
75. 作为记忆用户，我希望删除来源后关联记忆立即停用、来源彻底删除时清理，恢复来源后仍需确认启用，以便来源控制真实生效。
76. 作为记忆用户，我希望删除记忆后停止相关长期偏好检索和个性化，但保留来源原文，删除原文另行选择，以便区分忘记偏好与删除记录。
77. 作为隐私用户，我希望敏感偏好不被自动推断或收集，以便控制长期保存的信息。
78. 作为参谋用户，我希望主动点击或询问时才生成建议，以便首版不会每日自动处理数据或主动打扰。
79. 作为参谋用户，我希望建议说明原因、来源、有效期，并提供采纳、调整和忽略反馈，以便判断是否适合执行。
80. 作为参谋用户，我希望建议依据真实待办、日程和已授权记忆识别风险或安排优先次序，以便减少无依据的建议。
81. 作为参谋用户，我希望采纳前预览将修改的事项、确认执行成功才标记已采纳，以便建议不会越权或虚报完成。
82. 作为参谋用户，我希望依据变化后旧建议不可直接执行，须重新生成并确认，以便不执行过期方案。
83. 作为参谋用户，我希望忽略或修改反馈不自动成为长期人格标签，以便反馈不被过度解读。
84. 作为日常使用者，我希望正式使用前能手动导出加密备份，且不包含 API Key，以便安全保留记录。
85. 作为备份用户，我希望导出前知道备份内容和忘记独立口令无法恢复的后果，以便妥善管理备份。
86. 作为恢复用户，我希望先核对备份、查看摘要并得到备份现有数据的提示，再确认整库替换，以便避免意外覆盖。
87. 作为恢复用户，我希望恢复后提醒全部暂停、确认清单后重建，AI 上下文授权重新确认，以便恢复数据不等于自动恢复外部权限。
88. 作为隐私用户，我希望知道应用无法自动修改已导出的旧备份，恢复前提示已删记录可能重新出现，以便管理彻底删除的边界。
89. 作为故障排查用户，我希望诊断页面显示权限、模型连接、语音引擎、下次提醒及最近失败，以便理解不可用原因。
90. 作为首版验收者，我希望先在主力 OPPO 手机记录可重复的验证结果，再扩大机型适配，以便提醒能力建立在真实设备证据上。

## Implementation Decisions

1. **事实基线与先决验证**：当前本地工作区只有需求和领域文档，没有应用代码、构建配置或既有测试。先固定 MyBrain 的一个提交，验证构建和核心闭环，再决定基于其改造还是独立实现。不能把参考项目 README 的功能等同于本产品实现。具体工程基线、最低 Android 版本及技术栈尚未决定。
2. **领域边界**：遵循已确认的“待办与日程分别表达结果和时间安排”ADR。待办、日程、便签、提醒、长期记忆、参谋建议、会话、操作留痕分别承担职责，通过稳定标识关联；不通过复制文本伪造关联。一个待办可对应多个日程，一个日程最多对应一个待办。
3. **统一操作入口**：手动交互、文字和语音共用业务用例与校验规则。AI 只提出结构化意图及操作提案，业务层负责时间校验、确认凭证、幂等、事务及执行回执；模型不能自由执行 SQL 或绕过授权读取数据。模块的具体物理划分待工程验证后确定。
4. **确认与批量契约**：所有 AI 新增、修改、删除先预览，显示明确对象、日期、时区、重复规则及提醒；授权内查询可直接执行。批量创建先整批校验，任一失败则不写入；保存阶段也须保证本地批次不会出现未说明的部分成功。外部系统交接不伪装成本地事务可回滚操作。
5. **取消与结果核对**：未确认操作不执行；取消生成不能撤回已经确认且提交的真实操作，其结果仍可核对。执行具有稳定请求标识，重复点击或重试不产生重复事项；超时不自动判失败，未知结果标记待核实，核对真实记录后再报告。
6. **时间语义**：相对语言依据当前设备日期和本地时区解析，预览展示确定日期和时区；持久安排固定创建时区。时间点默认形成带截止的待办、明确时段形成日程，用户可改类型；日期截止不补具体时刻。日期计算及设备时区变化的具体实现属于技术设计验证项。
7. **重复生命周期**：固定日期规则下各次待办独立记录。支持每日、每周、每月、例外日期，仅本次或本次及以后修改、取消；单次延期不挪动后续实例。每月缺失日期落到月末，后续月份仍遵守原规则；子任务按每次重新开始并保留历史。
8. **事项生命周期联动**：完成、取消、删除分别表达不同事实。日程结束不自动完成；完成待办提示处理未来关联日程，未选则保留；删除日程保留待办，删除待办保留日程并解除关联。父子任务独立确认完成，父待办删除恢复连同子任务；提前完成或取消时经确认处理未完成子任务提醒。
9. **提醒契约**：截止不等同提醒，默认自动提醒关闭；支持多个提醒并去重。相对提醒随事项移动，独立时刻提醒不随之移动。普通通知可按平台能力调度，显式准时要求须检查能力；权限不足保留事项并标记未就绪，降级须确认。事项修改、取消、删除及恢复必须一致更新提醒状态，不以调度请求成功宣称实际触发。
10. **Android 集成**：首版自有提醒是通知、提示音和振动，不实现自有持续响铃。系统时钟通过平台公开能力交接，记录待核对状态及失败回退；不以打开页面认定保存，不自动同时创建自有提醒。指定任意日历日期的持续响铃不作承诺，不静默丢掉日期。
11. **离线和设备变化**：手动 CRUD、浏览和本地提醒独立于 DeepSeek。重启后重建有效调度，错过提醒合并提示、不逐项补响。时区变化、时间手动调整、休眠、省电和权限撤销需要可观察状态及设备测试。
12. **回收站和恢复**：普通日程、待办、便签回收站保留三十天，可立即彻底删除；回收站不参与提醒、检索或建议。恢复时仅处理未来提醒并重新检查权限；已完成或取消待办重新激活前展示提醒清单。父待办恢复后已解除的日程关联如何恢复仍属技术设计未决，不可擅自自动重连。
13. **模型接入和隐私**：用户自填 DeepSeek Key、模型及 Base URL；Key 掩码、安全存储和日志脱敏。当前消息外的当前会话及少量相关记录在说明并取得一次授权后按需发送，各类可独立关闭；关闭后提供本地回退或重新授权入口。对话历史和长期记忆保持区分，不引入应用代付、账号或充值。
14. **语音契约**：优先使用 Android 系统识别及中文 TTS，不要求额外语音 Key；不保证设备预装或完全离线。按住录音、松手转写、可编辑且点击发送后才提交；播报默认关闭，可停止。清晰呈现录音状态，退出页面不后台监听，不持久保存原始录音，缺少能力时回退键盘。
15. **长期记忆**：仅明确要求记住并确认后保存，保留类型、内容、来源、确认状态、时间与有效期等管理信息。冲突先由用户处理；停用、过期和删除影响后续检索及上下文组装。删除来源立即停用关联记忆、彻底删除时清理；恢复来源不自动启用。删除记忆保留来源原文但停止相关长期偏好检索及个性化，明确删除来源才清原文。历史业务和便签知识引用原记录，不冗余复制为未经授权的事实。
16. **参谋建议**：先根据真实记录筛选风险，再按授权调用模型组织建议；首版只主动触发。每条包含依据、有效期和可预览动作，反馈不自动形成长期人格标签。依据改变后旧动作不可直接执行；执行成功才标记采纳，失败不标记已采纳。
17. **备份**：日常使用前具备手动独立口令加密备份，排除 API Key。恢复先核对并展示摘要，提示备份当前数据，经确认整库替换，不合并。恢复后的提醒全暂停、确认后重建，AI 上下文授权重新确认；旧外部备份由用户管理，删除当前数据不承诺改写旧备份。
18. **保留能力和导航**：沿用五个底栏、二级管理入口、月视图及日程列表、便签标签置顶搜索、待办优先级类别、对话历史与流式回复、记忆来源管理及权限诊断。首页以今天的安排和快捷记录为主。系统日历读取、导入及双向同步不在首版。
19. **开发交付约束**：后续开发关联此规格或对应子任务并标明原 PRD 功能及验收编号；代码改动配套适当自动化测试，交付前运行适用检查。完成变更按独立提交组织并关联 Issue。引入依赖前核对许可证、兼容性、离线行为和维护状态；不将密钥、原始录音或完整私人日历写入版本历史或日志。本次发布规格不启动功能实现。

## Testing Decisions

### 已确认的测试边界

用户已确认采用一个主要测试边界：**应用用例入口的可观察行为**。从手动操作或 AI 提案的统一业务入口提交输入、确认或取消，使用真实本地持久化实现，检查用户可查询的数据、关联、状态、提醒调度意图和操作回执。通过可控制的时间、模型与平台适配器覆盖故障；不依赖真实云模型的随机输出完成日常自动化测试。

若最终采用的工程已有满足这一层级的用例或集成测试入口，优先复用，避免重复建立测试接口。当前没有既有代码或同类测试可引用；不得把尚未核查的 MyBrain 测试作为已具备能力。

Android 通知投递、重启恢复、系统时钟交接、麦克风及语音引擎行为，必须补充平台集成和实机测试。主要业务测试边界不能替代设备验证，也不要求为追求单一边界而伪装实际通知和响铃结果。

### 好测试的标准

- 测输入、用户确认、持久化后可查询结果、可见状态和真实回执，不测试私有函数、调用顺序或内部类布局。
- 对业务规则使用确定输入与可控制时间；以固定模型响应测试提案，另做有限真实端到端服务验证。
- 覆盖成功、拒绝、取消、权限不足、重复请求及结果未知；既验证正确结果，也验证没有未确认写入、重复事项或错误外发。
- 关联模块联测，重点覆盖待办、日程、子任务、提醒、回收站、记忆、建议及备份的生命周期一致性。

### 必测场景

| 场景 | 输入与动作 | 可观察结果 |
| --- | --- | --- |
| 离线核心功能 | 断网或不配置 Key 后新增、修改、重开应用 | 日历、待办、便签真实保存且可查询；模型失败不阻断手动操作 |
| 时间解析 | 时间点、明确时段、日期截止、模糊指代、跨日 | 类型及日期预览正确；歧义先追问；非法时段拒绝；日期截止不补时刻 |
| 完成与关联 | 日程结束、提前完成待办、删除日程或待办 | 独立状态和保留规则正确，提醒变化可核对 |
| 父子任务 | 子任务全部完成、提前完成或取消父待办、删除恢复 | 不自动勾选，提醒须确认停止，父子结构一致恢复 |
| 重复规则 | 每日、每周、每月、例外日期、闰年及夏令时边界 | 每次独立，月末处理正确；过去记录不被整组修改覆盖 |
| 重复延期 | 单次延期至已有下一次的日期 | 两次独立存在，预览提示，不挪动后续规则 |
| 重复子任务 | 多次执行并修改本次或本次及以后步骤 | 当次完成状态独立，历史不被重置 |
| 提醒语义 | 多个提醒、重复提醒、移动事项时间 | 去重；相对提醒移动，独立提醒不动，过期项明确显示 |
| 权限与调度 | 禁通知、无精确提醒能力、撤销权限 | 事项保留，提醒未就绪，无静默降级，提供修复入口 |
| 设备状态 | 重启、休眠、省电、改时区或手动改时间 | 调度恢复或明确不可用；错过提醒合并提示，不逐条补响 |
| 系统闹钟 | 支持、不支持、无保存回执、指定未来日期 | 真实交接及回退，不宣称未核实成功、不丢日期、不自动双份提醒 |
| 提案确认 | 查询、单条及批量写入、修改、删除、取消 | 查询按授权执行，所有 AI 写入确认前不落库，取消不写入 |
| 批量原子性 | 两项中一项校验失败或本地保存阶段故障 | 整批无新增，不显示虚假的部分或全部成功，修正后可重新确认 |
| 幂等与结果未知 | 重复确认、响应丢失、页面退出、重试 | 不重复创建；以真实执行记录核对，未知不冒充失败或成功 |
| 语音回退 | 拒绝麦克风、无识别器、TTS 不可用、离开页面 | 中文说明及键盘回退；编辑转写后才发送；录音停止，确认不绕过 |
| 上下文授权 | 未授权、分别关闭类别、无相关记录 | 不发送未授权数据；提供本地回退，不伪造个性化依据 |
| 记忆生命周期 | 显式保存、新会话、冲突、过期、停用、删除来源及恢复 | 只用已授权有效记忆；冲突不覆盖；索引及上下文不继续使用失效记忆 |
| 记忆与来源分离 | 删除记忆但保留聊天或便签 | 原文仍可查看，不再用于相关长期偏好检索与个性化；不误删整个来源 |
| 建议有效性 | 主动请求、未采纳、失败、来源修改或删除 | 不后台自动生成；采纳前无写入，失败不标已采纳，旧提案不可直接执行 |
| 回收站 | 删除、恢复、三十天清理、立即彻底删除 | 无提醒、无 AI 检索或建议，恢复不补响；非普通记录不误套三十天规则 |
| 备份与恢复 | 正确及错误口令、无效备份、覆盖确认、旧备份 | 导出不含 Key；先核对与确认再替换；恢复提醒暂停且授权重置，提示旧数据重现 |
| 安全及诊断 | 模型或平台故障、查看日志和权限诊断 | Key 不出现在日志，失败可诊断，权限、引擎及下次提醒状态可观察 |

首轮实机记录需包含 OPPO 型号、系统版本、权限状态、操作步骤和结果，当前设备详情待补充。后续扩大适配及发布时再覆盖至少两家主流厂商；不能将单机结果表述为全机型兼容。

原 PRD AT-01 至 AT-12 按本规格映射执行，其中 AT-05 的下一系统闹钟展示属于 P1，不作为首版阻塞。首版必须验证 CRUD、重复、预览确认、语音回退、记忆删除、建议依据、提醒重启恢复及手动备份恢复；性能阈值待基准设备确定后设定，不虚构已验证数值。

## Out of Scope

- 云端跨设备实时同步、多人协作、账号、充值及应用代付。
- 首版系统日历读取、导入及双向同步，周日视图增强。
- 读取全部系统或第三方闹钟、保证第三方闹钟编辑删除、绕过 Android 沙箱。
- 自有持续响铃及响铃页、指定任意日历日期的持续响铃承诺、首版下一系统闹钟展示。
- 全天后台热词唤醒、持续监听、连续语音对话、离线全链路及离线自然语言解析保证。
- 自动记忆提取候选、未经确认保存偏好、敏感属性推断、部署独立 Mem0 后端。
- 每日自动参谋建议、主动后台建议通知、从反馈自动推断人格、未经确认执行建议。
- 备份合并、自动云备份、自动修改外部旧备份、找回遗失的独立备份口令。
- 便签清单与待办自动互转、附件及语音备忘增强、知识图谱、复杂依赖和长期目标策略。
- 本次任务中的功能开发、构建验证、代码提交、PR 或部署；本次仅整理并发布规格。
